Flat collection of CommonJS modules deployed as Vercel/Node serverless functions under `api/`, each file exporting a `(req, res) => ...` handler. `_session.js` is the sole shared dependency providing session issuance/validation via an HMAC-SHA256 signed cookie (`dsa_tracker_session`) carrying a base64url-encoded expiry payload; it also exposes `safeEqual` for timing-safe comparisons. `auth.js` mounts at `/api/auth` and handles GET (status), POST (sign-in against `APP_ACCESS_PASSWORD`), and DELETE (sign-out). `state.js` mounts at `/api/state` and `solutions.js` mounts at `/api/solutions`; both are guarded by `hasSession(req)` and lazily ensure their single-row tables (`dsa_tracker_state`, `dsa_solutions`) via a module-scoped `ensureTablePromise` so `CREATE TABLE IF NOT EXISTS` runs once per cold start. There are no cross-imports between route handlers — dependency direction is strictly one-way: route handlers → `_session.js` + `@neondatabase/serverless`. Configuration is entirely environment-driven (`SESSION_SECRET`, `APP_ACCESS_PASSWORD`, `DATABASE_URL`, optional `VERCEL` for Secure cookies). The `f/` entry in the tree appears to be a non-JS artifact and is not imported by any handler.
